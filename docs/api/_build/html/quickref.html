Quick Reference

This page provides quick links to commonly used Mellea functions and methods.

Core Session Methods

The MelleaSession object (typically named m) provides the main interface for Mellea operations.

Creating a Session

import mellea
m = mellea.start_session(backend="openai/gpt-4")

Key Methods

instruct

Generate text based on instructions with optional requirements and sampling strategies.

MelleaSession.instruct(description, *, images=None, requirements=None, icl_examples=None, grounding_context=None, user_variables=None, prefix=None, output_prefix=None, strategy=<mellea.stdlib.sampling.base.RejectionSamplingStrategy object>, return_sampling_results=False, format=None, model_options=None, tool_calls=False)[source]

Generates from an instruction.

Parameters:

  • description (str) – The description of the instruction.

  • requirements (list[Requirement | str] | None) – A list of requirements that the instruction can be validated against.

  • icl_examples (list[str | CBlock] | None) – A list of in-context-learning examples that the instruction can be validated against.

  • grounding_context (dict[str, str | CBlock | Component] | None) – A list of grounding contexts that the instruction can use. They can bind as variables using a (key: str, value: str | ContentBlock) tuple.

  • user_variables (dict[str, str] | None) – A dict of user-defined variables used to fill in Jinja placeholders in other parameters. This requires that all other provided parameters are provided as strings.

  • prefix (str | CBlock | None) – A prefix string or ContentBlock to use when generating the instruction.

  • output_prefix (str | CBlock | None) – A string or ContentBlock that defines a prefix for the output generation. Usually you do not need this.

  • strategy (SamplingStrategy | None) – A SamplingStrategy that describes the strategy for validating and repairing/retrying for the instruct-validate-repair pattern. None means that no particular sampling strategy is used.

  • return_sampling_results (bool) – attach the (successful and failed) sampling attempts to the results.

  • format (type[TypeVar(BaseModelSubclass, bound= BaseModel | None)] | None) – If set, the BaseModel to use for constrained decoding.

  • model_options (dict | None) – Additional model options, which will upsert into the model/backend’s defaults.

  • tool_calls (bool) – If true, tool calling is enabled.

  • images (list[ImageBlock] | list[Image] | None) – A list of images to be used in the instruction or None if none.

Return type:

Union[ModelOutputThunk[str], SamplingResult]

Example:

from mellea.stdlib.sampling import RejectionSamplingStrategy

email = m.instruct(
    "Write an email to invite all interns to the office party.",
    requirements=["be formal", "Use 'Dear interns' as greeting."],
    strategy=RejectionSamplingStrategy(loop_budget=3),
)

Functional API

Mellea also provides a functional API for more advanced use cases.

instruct (functional)

mellea.stdlib.functional.instruct(description, context, backend, *, images=None, requirements=None, icl_examples=None, grounding_context=None, user_variables=None, prefix=None, output_prefix=None, strategy=<mellea.stdlib.sampling.base.RejectionSamplingStrategy object>, return_sampling_results=False, format=None, model_options=None, tool_calls=False)[source]

Generates from an instruction.

Parameters:

  • description (str) – The description of the instruction.

  • context (Context) – the context being used as a history from which to generate the response.

  • backend (Backend) – the backend used to generate the response.

  • requirements (list[Requirement | str] | None) – A list of requirements that the instruction can be validated against.

  • icl_examples (list[str | CBlock] | None) – A list of in-context-learning examples that the instruction can be validated against.

  • grounding_context (dict[str, str | CBlock | Component] | None) – A list of grounding contexts that the instruction can use. They can bind as variables using a (key: str, value: str | ContentBlock) tuple.

  • user_variables (dict[str, str] | None) – A dict of user-defined variables used to fill in Jinja placeholders in other parameters. This requires that all other provided parameters are provided as strings.

  • prefix (str | CBlock | None) – A prefix string or ContentBlock to use when generating the instruction.

  • output_prefix (str | CBlock | None) – A string or ContentBlock that defines a prefix for the output generation. Usually you do not need this.

  • strategy (SamplingStrategy | None) – A SamplingStrategy that describes the strategy for validating and repairing/retrying for the instruct-validate-repair pattern. None means that no particular sampling strategy is used.

  • return_sampling_results (bool) – attach the (successful and failed) sampling attempts to the results.

  • format (type[TypeVar(BaseModelSubclass, bound= BaseModel | None)] | None) – If set, the BaseModel to use for constrained decoding.

  • model_options (dict | None) – Additional model options, which will upsert into the model/backend’s defaults.

  • tool_calls (bool) – If true, tool calling is enabled.

  • images (list[ImageBlock] | list[Image] | None) – A list of images to be used in the instruction or None if none.

Return type:

Union[tuple[ModelOutputThunk[str], Context], SamplingResult[str]]

Returns:

A (ModelOutputThunk, Context) if return_sampling_results is False, else returns a SamplingResult.

Example:

from mellea.stdlib.functional import instruct
from mellea.stdlib.session import start_session

m = start_session(backend="openai/gpt-4")
result = instruct(
    "Write a haiku about programming",
    context=m.ctx,
    backend=m.backend
)

Creating Requirements

Requirements can be specified as strings or Requirement objects:

# Simple string requirements
m.instruct("Write code", requirements=["use Python", "include comments"])

# Using Requirement objects
from mellea.stdlib.requirement import Requirement

req = Requirement("Output must be valid JSON")
m.instruct("Generate user data", requirements=[req])
